Бинарь `cpu-slots-run` пакета `cpu-slots` (t-ve7e88): тяжёлая команда без своей единицы работы — ESLint (`--concurrency`), `tsgo`, `vite build`, `knip` — берёт слоты на весь прогон, с шириной.

## План
- **Контракт:** `cpu-slots-run [--max N] [--] <command> [args…]`.
  - Ждёт один слот (`acquireSlot`), затем без ожидания добирает свободные до `N` (по умолчанию `N = 1`).
  - Каждое вхождение `{slots}` в аргументах заменяется числом взятых слотов; то же число — в `CPU_SLOTS_WIDTH`.
  - Потомку передаётся метка `CPU_SLOTS_HELD` первого слота: вложенные раннеры проходят.
  - Команда идёт в своей группе процессов, сигналы пересылаются всей группе, код выхода пробрасывается; слоты держатся до её конца.
  - Пул выключен (не Linux, `CPU_SLOTS=0`) или слот предка — слотов не берёт, ширина `= N`.
- **Ядро:** `tryAcquireSlot(env)` — один проход по именам без ожидания, `Slot | null`; экспорт.
- **Общий код** запуска в группе с пересылкой сигналов и кодом выхода — `src/group.ts`, им пользуются `cpu-slots-node` и `cpu-slots-run` (сейчас логика живёт в `node-bin.ts`).
- **Разбор аргументов** строгий: неизвестная опция или `--max` без положительного целого — usage в stderr, код 2, команда не запускается.
- **Проверка** (Linux, тесты пакета):
  - при пуле 3 и одном слоте, занятом снаружи, `--max 4` даёт ширину 2 (`{slots}` и `CPU_SLOTS_WIDTH`), код выхода команды пробрасывается;
  - при пуле 1, занятом снаружи, команда не стартует, пока слот не освободится (отсутствие), затем идёт с шириной 1;
  - пока команда идёт, её слоты заняты: внешний ожидающий получает слот только после её конца;
  - на любой платформе при `CPU_SLOTS=0` — ширина `= N`, запуск сразу;
  - неизвестная опция — код 2, команда не запущена.
  - Сигналы проверяет уже существующий тест `cpu-slots-node` (общий `group.ts`).
- **README:** раздел про ESLint, `tsgo`, сборки.
- **Ревью:** plan-reviewer (1 круг); bug-reviewer (1 круг, добор).


## Сделано
- `cpu-slots-run [--max N] [--] <command>` в пакете `cpu-slots` (коммит `30977f1` репо `github.com/cevek/cpu-slots`), `tryAcquireSlot` в ядре, общий `src/group.ts` для обоих бинарей.
- Метка ширины — `@slots@`, не `{slots}`: zsh (логин-shell агентов на mini) и bash читают `{word}>файл` как перенаправление в именованный дескриптор, и аргумент исчезает до обёртки. Найдено вживую: `cpu-slots-run … --concurrency {slots} > lint.log` давал ESLint `[ '.', '--concurrency' ]`, через пайп — работало.
- Ширина: слот взят — число взятых; слот предка того же пула — 1; пула нет, потолок ожидания — `--max`.
- Группа процессов: своя сессия на верхнем уровне; внутри дерева держателя (`CPU_SLOTS_HELD` в env) — группа держателя, иначе отмена внешней обёртки оставляла вложенную команду жить. После выхода команды группа получает SIGKILL. Интерактивные команды не поддерживаются (нет терминала).
- Живая проверка на mini (копия admin-frontend, ESLint 10.4, zsh, вывод в файл): `cpu-slots-run --max 4 -- eslint . --concurrency @slots@` — ESLint получил `--concurrency 4`, код 0; `cpu-slots-run --max 4 -- env GOMAXPROCS=@slots@ tsgo` — код 0.
- Тесты: 38/38 на Linux, CI зелёный. Мутациями проверено, что тесты ловят: игнор `--max`, ширину без пула 1, отпуск слотов до старта, старт без ожидания, отсутствие SIGKILL группе, ширину `--max` во вложенном случае, сигнал только лидеру, потерю метки у потомка, вложенную команду в своей группе.
