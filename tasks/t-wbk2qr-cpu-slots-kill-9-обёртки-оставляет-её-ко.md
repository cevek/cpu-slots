Найдено замером памяти на mini: после `kill -9` обёртки `cpu-slots-node` раннер `node --test` и процесс тест-файла остались живы, тест-файл держал слот. Причина — `runInGroup` (`src/group.ts` пакета `cpu-slots`, github.com/cevek/cpu-slots) запускает команду с `detached: true` = новая сессия: SIGKILL обёртке не переслать, а убийство группы вызывающего (тайм-аут Bash-инструмента агента, `kill -- -pgid`) до команды не доходит. Сироты держат слоты и CPU; убийство по cgroup (claude-ui `stop`, `free_memory`) их достаёт.

Вариант: не уводить команду из группы вызывающего; сигнал обёртке пересылать всему поддереву через `/proc` (как `killTree` в `scripts/run-suites.mjs`); остатки после штатного выхода — либо задокументированная граница, либо снимок потомков раз в ~0.5 с и добивание выживших (с проверкой времени старта против переиспользования pid). Решение по семантике — за юзером: своя группа появилась по находкам ревью t-n0kakw.


## Решение (юзер)
Команда не уходит из группы вызывающего: убийство группы вызывающего (тайм-аут инструмента агента, `kill -- -pgid`) достаёт её вместе с обёрткой. Процессы, брошенные командой после штатного выхода, не добиваются — граница в README.

## Спецификация
- `src/group.ts`: спавн без `detached`. Сигнал обёртке (SIGINT/SIGTERM/SIGHUP) пересылается всему поддереву команды: на Linux обход `/proc/<pid>/stat` (ppid, время старта), в остальных ОС — `child.kill(sig)`.
- После пересылки сигнала снимок поддерева (pid + время старта) запоминается; когда команда выходит, выжившие из снимка с тем же временем старта получают SIGKILL — отмена тотальна, в том числе для вложенной обёртки и команды, игнорирующей SIGTERM. Штатный выход без сигнала никого не добивает.
- Ветка «внутри дерева держателя — без своей группы» больше не нужна: путь один.
- Тесты (`test/run-bin.test.ts`, `test/node-test.test.ts`): новый — убийство группы вызывающего (`kill(-pid обёртки, SIGKILL)`) убивает команду и освобождает слот; сохраняются — сигнал поддереву (лидер игнорирует SIGHUP, потомок подтверждает), отмена вложенных обёрток, SIGHUP `cpu-slots-node`; тест «остатки группы после выхода убиваются» удаляется.
- Каждая гарантия проверена мутацией на Linux.


## План (воркер mb-41c9002b, согласован)
1. `src/group.ts`: спавн без `detached`, путь один (ветка про `CPU_SLOTS_HELD` уходит). Linux: поддерево `child.pid` обходом `/proc/*/stat` (ppid, время старта; разбор после последней `)`).
2. Сигналы:
   - SIGTERM/SIGHUP — снимок поддерева `{pid, start}` в общее множество и сигнал каждому;
   - SIGINT — только снимок: с терминала его получает вся группа переднего плана, а второй SIGINT vitest/npm читают как форс-выход;
   - не Linux — `child.kill(sig)`, без снимка.
3. Выход команды: SIGKILL выжившим из снимка, у кого время старта совпадает, затем выход с её кодом. Без сигнала снимок пуст — никого не добиваем.
4. Тесты:
   - новые: `cpu-slots-node` + `kill(-pid обёртки, SIGKILL)` → слот тест-файла освобождается; `cpu-slots-run` + тот же kill → процесс команды мёртв (у `cpu-slots-run` слот в самой обёртке и освобождается и при своей сессии — не дискриминирует); `killSurvivors` на живом постороннем процессе: верное время старта → умер, на единицу больше → жив;
   - сохраняются: SIGHUP поддереву, отмена вложенных обёрток, SIGHUP `cpu-slots-node`;
   - удаляется: «остатки группы после выхода убиваются».
5. Мутации на mini, каждая делает свой тест красным:
   - `detached` обратно;
   - только `child.kill` на Linux;
   - без SIGKILL снимку;
   - без сравнения времени старта;
   - снимок на выходе вместо момента сигнала;
   - пересылка SIGINT.
6. README и doc-комментарий `group.ts`:
   - своей сессии нет — терминал сохраняется;
   - брошенное после штатного выхода живёт;
   - адресный SIGINT в pid обёртки до команды не доходит;
   - двойной SIGTERM/SIGHUP возможен;
   - вне Linux сигнал получает только прямой потомок.
7. Ревью кода: bug-reviewer; architecture не нужен — правка внутри `group.ts`, границы блоков те же.


## Правки плана после план-ревью
- **SIGINT пересылается поддереву**, если обёртка не в группе переднего плана своего терминала. Linux: `/proc/self/stat`, `tty_nr != 0 && tpgid == pgrp`; вне Linux — `process.stdin.isTTY`. Снимок — всегда. Тесты считают доставки: адресный без tty — 1, сигнал группе переднего плана PTY (`script -qec`) — 1.
- **Снимок дорастает** пересканом каждые ~100 мс после первого сигнала, пока команда не вышла: ловятся форки в обработчиках сигналов. Пределы в README: потомок, рождённый и брошенный между сканами; команда, игнорирующая SIGTERM, держит обёртку и слоты.
- **Время старта** перечитывается перед каждым сигналом. pidfd в Node нет; остаток окна принят (`pid_max` 4194304).
- **Тесты на наблюдаемые факты:** SIGHUP доходит до тест-файла (журнал); смерть внука — через `/proc` с учётом зомби; уборка потомков по pid в `finally`.
- **Судейское:** тест «брошенное после штатного выхода живёт» не пишется — он пиннит ограничение и покраснеет на правильной доработке. Ревьювер просил.
- **README:** адресный SIGKILL в pid обёртки оставляет команду жить; вне Linux пересылка только прямому потомку. Тест прямой доставки SIGTERM идёт и на macOS.
